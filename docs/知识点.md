## 一、必懂清单(方法核心,答辩命根子)

### Q1. W′ = W + ΔW 里的 W 是什么?为什么冻结它?

**关键词**:预训练权重 / 1.25 亿 / 冻结省显存省存储

**详细解释**:
- W 是预训练模型里已经学好的权重。在 RoBERTa 里,就是 12 层 encoder 里 attention 和 FFN 的线性层权重,共约 1.25 亿参数。
- "冻结" = 把 W 的 `requires_grad` 设为 False,不参与反向传播、不进 optimizer。
- 为什么要冻结:① W 是海量语料上学到的通用语言知识,不该被下游小数据集破坏(全量微调有"灾难性遗忘"风险);② 冻结后反向传播只算 A/B 那一小撮参数,显存和存储大幅下降;③ 冻结后 ΔW 是"任务特定增量",可以单独存、单独切换——一个底座 W + 多套 ΔW 就能适配多个任务。

### Q2. ΔW = BA,A/B 的形状、初始化,为什么这么设?

**关键词**:B=768×r 初始零 / A=r×768 随机 / 起点 ΔW=0

**详细解释**:
- 设原矩阵 W 是 d×d(d=768)。ΔW = B·A,其中 B 是 d×r、A 是 r×d,相乘得到 d×d,才能和 W 相加。
- r 就是"秩"(rank),r ≪ d(如 8 ≪ 768),所以 A/B 参数量 = d·r + r·d = 2dr,远小于 d²。
- 初始化:B 全零、A 随机高斯。这样训练开始时 ΔW = B·A = 0,等价于"从原始预训练模型出发",不会一上来就扰动预训练权重。
- 为什么是 B 零 + A 随机(不是反过来):A 随机负责给出一个随机的低秩方向,B 置零保证起点是 0,训练中 B 从 0 开始"长"出来。这是论文/官方实现的固定做法。

### Q3. 实际用的是 (α/r)·BA,α 和 r 分别管什么?

**关键词**:r→容量/秩 / α→强度/缩放 / α/r→实际系数

**详细解释**:
- 论文里实际使用 ΔW = (α/r)·B·A,α 是超参数、不参与训练。
- r 管"容量":A/B 能表达的 ΔW 的秩上限(自由度多少)。
- α 管"强度":把 ΔW 整体放大多少倍。α 越大,同样学到的更新被放得越大,作用类似"对更新幅度再乘一个系数"。
- 真正乘在 BA 上的是 α/r。论文经验做法:α 固定为第一个试的 r(如 r=8 时 α=8),使 α/r=1,之后只调 r 不再动 α。
- **消融时的关键**:要单独研究 r 的影响,必须保持 α/r 不变(即让 α=r);否则 r 变的同时缩放也在变,两个变量混在一起,结论不可靠。所以我们脚本里写了 `LORA_ALPHA = LORA_R`。

### Q4. r 越大意味着什么?对效果/参数量/过拟合的影响?

**关键词**:容量↑ / 参数↑ / 冗余+过拟合 / 倒 U

**详细解释**:
- r ↑ → A/B 参数 ↑(线性增长 2dr)→ 能表达的 ΔW 更复杂(容量↑)。
- 但 LoRA 的前提是"任务需要的 ΔW 本身是低秩的",所以超过某个 r 后,多出来的容量是**冗余**的,数据里没那么多信息给它学。
- 冗余的容量在小数据集上会去拟合噪声 → 过拟合 → 效果反而略降。
- 我们实测(SST-2,r=1/4/8/16 平均 acc 分别为 0.9329/0.9318/0.9369/0.9334):r=8 最高,再大略降,呈"倒 U",证明"不是 r 越大越好"。

### Q5. 为什么 LoRA 参数量大幅下降?

**关键词**:冻结底座 / 只训 A/B / 分类头是共有的

**详细解释**:
- 全量微调:约 1.25 亿参数全部可训练、全进 optimizer、全存梯度。
- LoRA:底座 W 全部冻结,只训练 A/B。r=8 时 A/B = 12 层 × 2 矩阵(Q/V)× 2·768·8 = 294,912 参数。
- **注意一个容易被问的点**:分类头(592,130 参数)两边**都要**训——它是加载模型时新初始化的、不在预训练权重里,所以 LoRA 省不掉它。报告里记的"LoRA 可训练参数 88.7 万" = A/B 29.5 万 + 分类头 59.2 万。
- 所以真正被 LoRA "省掉"的是底座那约 1.24 亿参数。总可训练参数 88.7 万 vs 1.25 亿,约 1/140。

### Q6. 为什么性能可能接近甚至超过 Full FT?

**关键词**:低秩假设 / 内蕴维度低 / 大模型过参数化

**详细解释**:
- 经验证据:论文在 GPT-3 等大模型上,LoRA 用极少参数就接近甚至超过全量微调。
- 一种直觉解释:预训练大模型是"过参数化"的,下游任务要改的方向其实集中在一个很低的"内蕴维度"(intrinsic dimension)里——有相关工作测过,大模型的内蕴维度远小于参数总数。所以用低秩的 ΔW 就能捕获主要更新方向,而不需要动全部参数。
- 这是"经验观察 + 直觉解释",不是严格证明(见 Q7)。

### Q7. 为什么"低秩就够用"不能说是严格普适证明?

**关键词**:经验假设 / 不普适 / 分任务

**详细解释**:
- LoRA 有效是**实验观察**出来的,不是从某条定理严格推出的。不同任务需要的 ΔW 秩可能不同(简单任务低秩够,复杂任务可能不够)。
- 论文自己也只是在若干任务/模型上报告结果并讨论 r 的影响,没有证明"任意任务都低秩"。
- 答辩要会说:这是"有直觉支撑的经验性假设",不是普适定理;所以实践中要针对任务调 r 验证,不能想当然。

### Q8. LoRA 相比 Adapter 的核心优势?

**关键词**:零推理延迟 / 合并 BA 进 W / 旁路

**详细解释**:
- Adapter 是在层里插一个小网络,推理时每一层都要额外跑这个小网络,增加**串行延迟**。
- LoRA 的 ΔW 是加在 W 旁边的低秩旁路,训练时冻结 W、只训 BA。
- 推理时可以把 BA **合并**进 W:W′ = W + (α/r)·BA,算一次就得到普通权重,之后推理和原始模型**完全一样、零额外延迟、零额外计算**。
- 这是 LoRA 相对 Adapter 的核心工程优势,面试常问。




### Q9. LoRA 在 PEFT 里的定位?

**关键词**:PEFT 基础方法 / 影响最大 / QLoRA·AdaLoRA·DoRA

**详细解释**:
- LoRA(2021)是参数高效微调(PEFT)里最经典、影响最大的方法之一,思路简洁:冻结 + 低秩增量。
- 后续衍生:QLoRA(把 LoRA 和 4-bit 量化结合,消费级显存就能微调大模型)、AdaLoRA(自适应分配秩)、DoRA(把方向/幅度分解来改进 LoRA)等。
- 定位要准确:**别说"最先进"**,要说"最基础、影响最广的之一,很多后续方法是它的变体"。

## 二、我们自己的实验发现

### 实验 1:Full FT vs LoRA(r=8)

| 方法 | dev accuracy | 可训练参数 | 显存峰值 | 训练时间 |
|---|---|---|---|---|
| Full FT | 0.9289 | 124,647,170 | 3164 MB | 2480 s |
| LoRA (r=8) | 0.9369 | 887,042 | 1529 MB | 1551 s |

- 结论:LoRA 用约 1/140 的参数、约 1/2 的显存,精度持平甚至略高。

### 实验 2:rank 消融(固定 qv,两个种子 42/123)

| r | seed 42 | seed 123 | 平均 |
|---|---|---|---|
| 1 | 0.9300 | 0.9358 | 0.9329 |
| 4 | 0.9289 | 0.9346 | 0.9318 |
| 8 | 0.9369 | 0.9369 | 0.9369 |
| 16 | 0.9323 | 0.9346 | 0.9334 |

- r=8 在两个种子里都精确等于 0.9369,最高且最稳;r=1/4/16 的排序在种子间会互换,三者差距(0.001~0.004)落在随机波动量级内。
- 结论:倒 U,r=8 最优;不是越大越好。

### 实验 3:target_modules 消融(固定 r=8)

| target | seed 42 | seed 123 | 平均 |
|---|---|---|---|
| qv | 0.9369 | 0.9369 | 0.9369 |
| qkv | 0.9346 | 0.9358 | 0.9352 |

- qv ≥ qkv 在两个种子里都成立,但幅度(0.0017)在噪声内。
- 结论:加 K 无增益(方向与论文 §7.1 "Q/V 是最优子集"一致),且多 14.7 万参数、约 100MB 显存。

### 论文原始结果 vs 我们的结果(为什么有差异)

- 论文报 RoBERTa-base + LoRA 在 SST-2 dev 约 95.1(0.951);我们得到 0.9369,略低。
- 可能原因:① 随机种子 / 数据划分不同;② 超参(学习率、epoch、batch)不同;③ 我们只训 3 个 epoch,可能欠拟合;④ 分类头要从头训,细节可能不同;⑤ transformers/PEFT 版本差异;⑥ 论文可能用了我们没用到的 trick(更精细的 LR 调度、不同的 α 等)。
- **关键态度**:论文 95.1 是"参考上限",不是 KPI。我们验证的是"参数量大幅下降 + 精度接近 Full FT + rank/target 的影响"这套逻辑,而不是去刷 95.1。
